## 6. Core backend functionality
Implement all required functionality from `BRIEF.md` and `PIGEON.md`.

Pay particular attention to:

### Authentication and authorization

- Integrate with the supplied Mock Identity Provider.
- Implement the required login/session flow.
- Identify the authenticated user and workspace membership.
- Support multiple workspaces.
- Enforce workspace-level data isolation on every relevant API.
- Support the supplied admin and agent roles as specified.

### Webhook ingestion

- Integrate with the Pigeon simulator.
- Verify webhook signatures using raw request bodies and HMAC-SHA256 as required.
- Validate webhook timestamps within the required five-minute window.
- Implement event-ID idempotency.
- Prevent duplicate message storage.
- Handle out-of-order events and delivery statuses.
- Preserve the correct event and message ordering using the provider's timestamps and identifiers.
- Acknowledge valid webhooks within the required five-second limit.
- Follow all retry and failure rules documented in `PIGEON.md`.

### Conversations and messages

- Store inbound messages.
- Create or update conversations correctly.
- Retrieve inbox conversations.
- Retrieve conversation message history.
- Support assignment to human agents.
- Support sending replies through Pigeon.
- Handle provider responses and delivery statuses.
- Support private notes if required by the assessment.

### Realtime updates

- Implement WebSocket events only as required.
- Notify connected workspace users about relevant conversation and message changes.
- Prevent information from one workspace reaching another workspace.
Do not assume that an AI agent is required. The assessment's agents are human support agents.
